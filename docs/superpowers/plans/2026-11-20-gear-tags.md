# Gear Tags and Scan Check In / Check Out: Implementation Plan

**Goal:** QR asset tags on LRE gear, scanned from a phone to check pieces out to an event and back in.

**Spec:** `docs/superpowers/specs/2026-11-20-gear-tags-design.html` (approved by David 2026-11-20).

**Approved choices:** tiered tagging ($250 and up plus cases), tags printed "LRE Productions" + number from 0001, scans feed the event gear checklist, all seven scan features. Owner (Vident, Luke's company, LRE) is kept in the hub, never on the tag. All admins and staff can scan. Staff can only suggest additions, changes and removals; an admin approves. Admins edit freely.

**Architecture:** One tag = one row in `av_product_units` (new `tag_number`). A scan resolves the tag to a unit, ticks the matching line on the event's gear checklist (existing `event_checklist_checks`, whose triggers already mirror to the Warehouse ledger), flips the unit's `status`, and appends to a new `gear_tag_scans` log. Writes go through the service-role client after an app-side role check, because the checklist RLS only lets assigned staff write and David wants every staff member able to scan.

**Tech:** Next.js 16 App Router, Supabase, vitest. QR decode: `BarcodeDetector` where the browser has it, `jsqr` otherwise.

## Global constraints

- Tag number: 4 to 6 digits, stored as text, unique, never reused. QR may hold `https://hub.lreproductions.com/t/0001`, `LRE-0001` or `0001`; all three must scan.
- Guests cannot open any of it. A signed-out scan lands on the login page and returns to the tag after sign-in.
- LRE repo, LRE Supabase project and LRE Vercel project only.
- AGENTS.md registrations: changelog, sidebar + Tools, search, Ask the Hub guide, pending how-to video.

## Review focus

1. A scan made with no signal must not be lost: queue on the phone, replay once, never double count (`client_id`).
2. A tag the hub has never seen: offer linking, not an error.
3. A piece scanned out twice, or back when it was never out: record it, warn, do not corrupt checklist counts.
4. An event whose checklist line is already full: the extra piece still gets a line.
5. A case scan moves every piece assigned to that case.
